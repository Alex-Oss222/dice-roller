# LLM chatbot long-running state: context limits, degradation, compaction and cross-chat persistence (2025-2026)

Research date: 2026-09-23. Scope: what a solo tabletop-RPG campaign run inside a chatbot can safely keep in the transcript versus in external files retrieved on demand.

Sourcing note for the report writer: Anthropic's platform docs (platform.claude.com), Claude Code docs (code.claude.com), Anthropic engineering blog and the adobe-research/NoLiMa GitHub README were fetched in full. The Chroma report, OpenAI help pages, Google support pages, arXiv and support.claude.com were blocked by the network egress proxy, so figures from them come from search-result summaries and secondary write-ups; each such finding is marked "(via search summary / secondary)". Numbers marked that way should be treated as reliable in direction and approximately right in magnitude, but should be re-verified against the primary page before being quoted as exact.

## Key question 1: How large are current context windows, and at what fill level does recall and instruction-following measurably degrade?

### Takeaway
Advertised windows are now 200K-1M tokens (API) but measured "effective" lengths for anything beyond literal-match retrieval are far shorter: NoLiMa puts most 2025 frontier models' effective length at 2K-16K tokens, and Chroma's July 2025 report found all 18 tested models degrade before their limit. Vendors themselves now document "context rot" and tell you to curate context rather than fill it.

### Cited Findings

Context window sizes (vendor-stated):
- Claude Fable 5.1, Mythos 5.1, Fable 5, Mythos 5, Opus 5.5, Opus 5, Opus 4.8, 4.7, 4.6, Sonnet 5, Sonnet 4.6 and Mythos Preview have a 1M-token context window with up to 128K output tokens; other models including Sonnet 4.5 have 200K. 1M is the default for those models with no beta header and standard pricing. — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- "As token count grows, accuracy and recall degrade, a phenomenon known as context rot. This makes curating what's in context just as important as how much space is available." — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- Everything counts toward the window: system prompt, all messages including tool results, images and documents, tool definitions, and the generated output including extended thinking. On Opus 4.5+, Sonnet 4.6+ and Fable/Mythos models, previous thinking blocks are kept in context by default and count as input tokens. — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- Claude.ai consumer plans: "On paid plans, the newest models support up to a 1M token context window, while others support 500K or 200K tokens." A portion of the window is always reserved for the response. — [Claude Help Center, usage and length limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) (fetched via WebFetch summary)
- ChatGPT (via search summary of a third-party plan table, Sept 2026): instant models 27K tokens on Free, 54K on Go/Plus/Business, 128K on Pro/Enterprise; reasoning models 256K on Go/Plus/Business/Enterprise and 400K on Pro; API GPT-6 Astra and GPT-5.6 family accept 1,050,000 tokens with a 128,000 output cap. These are total windows (input plus output), and OpenAI notes that instructions, memories and reasoning share the space. — [ai-toolbox.co, ChatGPT context window by plan (2026)](https://www.ai-toolbox.co/chatgpt-models/chatgpt-context-window-token-limits-2026) (secondary; primary chatgpt.com/pricing was egress-blocked)
- Gemini 3 / 3.1 Pro: 1M-token input context window, up to 64K output tokens; available in the Gemini app for Pro and Ultra subscribers (via search summary). — [Google AI for Developers, Gemini 3 developer guide](https://ai.google.dev/gemini-api/docs/gemini-3); [DeepMind Gemini 3.1 Pro model card](https://deepmind.google/models/model-cards/gemini-3-1-pro/)
- Claude 4.7+ models use a newer tokenizer that produces approximately 30% more tokens for the same text than Sonnet 4.6 and earlier. Rough rule: 1 token is about 4 characters or 0.75 English words. — [Anthropic, Pricing](https://platform.claude.com/docs/en/about-claude/pricing)

Measured degradation with length:
- NoLiMa (Adobe Research, ICML 2025; results updated through 2025-07-17): needles with minimal lexical overlap to the question. GPT-4o base 99.3%, effective length 8K, scores 98.1% (1K), 98.0% (2K), 95.7% (4K), 89.2% (8K), 81.6% (16K), 69.7% (32K). GPT-4.1 base 97.0%, effective length 16K, 79.8% at 32K. Llama 3.3 70B base 97.3%, effective length 2K, 42.7% at 32K. Llama 3.1 405B fell from 94.7% base to 48.4% at 32K. At 32K, ten models dropped below 50% of baseline. — [adobe-research/NoLiMa README](https://github.com/adobe-research/NoLiMa)
- NoLiMa: GPT-4o fell to 56% at 128K; "effective length" is defined as the longest context at which the score stays above 85% of base; 11 of 13 models dropped to 50% or less of baseline at 32K. — [NoLiMa arXiv 2502.05167](https://arxiv.org/abs/2502.05167v3) (via search summary)
- NoLiMa-Hard, reasoning models: GPT-o3 100% base, 94.4% (4K), 86.2% (8K), 74.9% (16K), 58.5% (32K); GPT-o1 99.9% base, 31.1% at 32K. — [adobe-research/NoLiMa README](https://github.com/adobe-research/NoLiMa)
- Chroma "Context Rot" (July 14, 2025; Hong, Troynikov, Huber): 18 models including GPT-4.1, Claude 4, Gemini 2.5, Qwen3; "model reliability decreases significantly with longer inputs, even on simple tasks like retrieval and text replication"; as semantic similarity between needle and question decreases, degradation with length accelerates. — [Chroma, Context Rot](https://www.trychroma.com/research/context-rot) (via search summary; page egress-blocked); replication toolkit at [chroma-core/context-rot](https://github.com/chroma-core/context-rot)
- Chroma LongMemEval experiment: a roughly 113K-token full chat history versus a roughly 300-token focused extract containing the same relevant content; models did well on the focused input and showed "consistent performance degradation" on the full input. — [Chroma, Context Rot](https://www.trychroma.com/research/context-rot) (via search summary)
- Chroma: models performed slightly better when the haystack was randomly shuffled than when it kept its logical flow, i.e. structural coherence of the surrounding text can make the target harder to find. — [Chroma, Context Rot](https://www.trychroma.com/research/context-rot) (via search summary)
- Secondary summaries of Chroma report 20-50% accuracy drops from 10K to 100K+ tokens on NIAH-style tasks and say Claude models decayed slowest of those tested. — [Nadir blog summary](https://getnadir.com/blog/context-rot-long-context-degradation-cost/); [Morph, context rot guide](https://www.morphllm.com/context-rot) (secondary; not verified against primary)
- Lost in the Middle (Liu et al., 2023 preprint / TACL 2024; OLDER than the 2025 cutoff): in 20-document multi-document QA, accuracy is highest with the relevant document first, nearly as high when last, and drops 20-30+ points when it sits in the middle; effect seen in GPT-3.5-Turbo, Claude-1.3, MPT-30B, LongChat-13B. — [Liu et al., Stanford PDF](https://cs.stanford.edu/~nfliu/papers/lost-in-the-middle.arxiv2023.pdf) (via search summary); a 2026 theory paper models the U-shape as intrinsic transformer position bias — [Lost in the Middle at Birth, arXiv 2603.10123](https://arxiv.org/html/2603.10123)
- RULER (2024; OLDER): almost all models exhibit large drops as context grows even when they ace vanilla NIAH; only Jamba-1.5 had a confirmed effective length of 256K in that report. — [RULER, alphaXiv](https://www.alphaxiv.org/abs/2404.06654) (via search summary)
- LongMemEval (Oct 2024, ICLR 2025; OLDER but foundational for chat memory): 500 questions over scalable chat histories; long-context LLMs show a 30%-60% performance drop on LongMemEval-S, and commercial assistants such as GPT-4o scored only 30%-70% on a much simpler setting. Tests five abilities: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention. — [LongMemEval arXiv 2410.10813](https://arxiv.org/abs/2410.10813); [GitHub](https://github.com/xiaowu0162/longmemeval) (via search summary)
- LOCA-bench (Feb 2026): agent benchmark with environment descriptions of 8K-256K tokens; "as the amount of context grows, agent reliability often deteriorates"; context management (removing stale tool results, stripping thinking, compaction, memory tools, programmatic tool calling) "can substantially improve the overall success rate", with frontier models benefiting more. — [LOCA-bench arXiv 2602.07962](https://arxiv.org/abs/2602.07962); [GitHub](https://github.com/hkust-nlp/LOCA-bench) (via search summary; results page egress-blocked)
- Anthropic's engineering guidance (Sept 29, 2025) frames this as a finite "attention budget": transformer attention creates n^2 pairwise relationships, so every added token depletes attention; context rot affects all models at varying rates. — [Anthropic, Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### Inferences
- For a campaign, "how full is the window" is the wrong safety metric. The NoLiMa numbers show that recall of facts that must be inferred rather than string-matched (e.g. "the prince we hold" = Rhaegar captured in turn 3) already loses 10-30 points by 16K-32K tokens on 2025 frontier models. A 40-turn transcript at roughly 1.5K-3K tokens per turn is 60K-120K tokens, well past every measured effective length in NoLiMa.
- Retrieval of an exact string ("Rhaegar") stays strong far longer than reasoning over it; so a compact, explicitly-worded state sheet placed near the end of the prompt (recency position) is the format most likely to be used correctly.
- The Chroma shuffled-haystack result suggests narrative prose is a bad substrate for state: coherent story text makes embedded facts harder, not easier, to find.

### Gaps
- Chroma's per-model accuracy curves (exact percentages at 10K/100K/1M) could not be read from the primary page (egress-blocked); only secondary summaries were available.
- No vendor publishes a "degradation starts at X% fill" number for their chat products; the fill-level answer must be inferred from benchmarks.
- NoLiMa has no published results for Claude 4.x/5 or Gemini 3 models; the GitHub table covers GPT-4o/4.1, o1/o3, Llama, Gemma, Gemini 1.5-era models.
- LOCA-bench per-strategy success rates were not retrievable (arXiv and project site blocked).

## Key question 2: What do studies show about LLMs remembering facts established early in a very long chat by turn 40?

### Takeaway
Benchmarks built specifically on multi-session chat histories (LongMemEval, Chroma's LongMemEval replication) show 30-60% accuracy loss when the same facts are buried in a 100K+ token transcript versus a ~300-token focused extract, and facts that require an update or temporal reasoning ("we captured him, then he escaped") are the weakest category. Early-position facts are helped by primacy bias, but middle-of-transcript facts are the ones most often lost.

### Cited Findings
- LongMemEval: long-context LLMs show a 30%-60% drop on LongMemEval-S; the five tested abilities are information extraction, multi-session reasoning, temporal reasoning, knowledge updates and abstention. — [LongMemEval arXiv 2410.10813](https://arxiv.org/abs/2410.10813) (via search summary; paper is Oct 2024, ICLR 2025)
- Chroma re-ran LongMemEval with ~113K-token full histories versus ~300-token focused inputs; models were "highly capable" on focused inputs and degraded consistently on full inputs, attributing this to irrelevant context rather than to the length of the answer-bearing content. — [Chroma, Context Rot](https://www.trychroma.com/research/context-rot) (via search summary)
- Lost in the Middle: accuracy is highest for information at the very beginning (primacy) and end (recency) and drops 20-30 points for the middle of a 20-document context. — [Liu et al.](https://cs.stanford.edu/~nfliu/papers/lost-in-the-middle.arxiv2023.pdf) (2023; via search summary)
- NoLiMa: when the question does not literally share words with the needle, GPT-4o accuracy fell from 99.3% to 69.7% at 32K and 56% at 128K. — [adobe-research/NoLiMa README](https://github.com/adobe-research/NoLiMa); [arXiv](https://arxiv.org/abs/2502.05167v3)
- Chroma's "repeated words" experiment showed models fail even at exact text replication as length grows (via search summary). — [Chroma, Context Rot](https://www.trychroma.com/research/context-rot)
- Anthropic's own harness guidance identifies "lost context" as a documented failure mode of long-running agents and prescribes progress files so the agent does not "guess what happened". — [Anthropic, Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Nov 26, 2025)
- CogCanvas (Jan 2026) proposes "compression-resistant cognitive artifacts" specifically because facts and decisions are lost when long conversations are summarized or truncated. — [CogCanvas arXiv 2601.00821](https://arxiv.org/html/2601.00821v1) (title/abstract via search only; page egress-blocked, numbers not retrieved)

### Inferences
- A fact stated once in turn 3 and never restated is in the worst position by turn 40: it is in the middle of the transcript (not primacy, not recency), phrased in narrative rather than the words a later question will use (NoLiMa's failure mode), and, if the chat product has compacted, may have been summarized into a sentence or dropped.
- A "knowledge update" (captured in turn 3, ransomed in turn 20) is the category LongMemEval flags as weakest for long-context models, so the transcript alone is likely to produce stale-state errors (still treating the prince as captive).

### Gaps
- No study found that directly measures "turn N recall" in a 40-turn creative RPG transcript; the closest proxies are LongMemEval (chat assistant histories) and NoLiMa (semantic needles).
- The exact LongMemEval per-model numbers for 2025-2026 models (Claude 4.x, GPT-5.x, Gemini 3) were not found; the available figures are for GPT-4o-era models.

## Key question 3: What is the vendor-documented behaviour when a chat exceeds context, and what gets dropped?

### Takeaway
Claude documents three mechanisms: a hard API error when input alone exceeds the window, a first-in-first-out rolling window in claude.ai chat, and (newer) automatic summarization of earlier messages; Claude Code and the API compaction feature replace old turns with a structured summary that keeps decisions and pending work but discards verbatim tool output and detail. ChatGPT and Gemini behaviour is only documented second-hand: oldest turns are silently dropped or summarized.

### Cited Findings
Claude (API):
- "If the input alone already exceeds the model's context window, the API returns a 400 invalid_request_error ('prompt is too long') on every model." On Claude 4.5+ models, if input plus max_tokens exceeds the window the request is accepted and generation stops with stop_reason model_context_window_exceeded. — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- Footnote: "Chat interfaces such as claude.ai can also manage the context window on a rolling 'first in, first out' basis." — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- Server-side compaction: "Compaction replaces the older turns of a conversation with a summary that Claude writes on the server... it keeps the active context small, because response quality degrades as a conversation grows." Two modes: on-demand (beta header compact-2026-09-04, top-level compaction parameter, returns a signed compaction block that you send back in place of the summarized messages; can keep recent turns word-for-word and run in the background) and threshold compaction (the API compacts inside the request when input tokens reach a trigger you set; "The API drops what came before the block"). You can supply your own summarization prompt "when the default summary drops something a later turn needs". Available in beta for Claude 4.6 and later. — [Anthropic, Compaction overview](https://platform.claude.com/docs/en/build-with-claude/compaction)
- Threshold compaction launched in beta January 2026 with header compact-2026-01-12 for Opus 4.6 and Sonnet 4.6 (via search summary). — [openclaw issue tracking the feature](https://github.com/openclaw/openclaw/issues/13752); [Claude Cookbook, automatic context compaction](https://platform.claude.com/cookbook/tool-use-automatic-context-compaction)
- Context editing offers rule-based alternatives: clearing old tool results and clearing thinking blocks. — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- Context awareness: on Sonnet 5, Sonnet 4.6, Sonnet 4.5 and Haiku 4.5 the API injects a token budget and, after each tool call, a warning like "Token usage: 35000/200000; 165000 remaining"; Opus 4.7+ and Fable/Mythos do not receive these tags. — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)

Claude (claude.ai chat):
- "When your conversation approaches the context window limit, Claude summarizes earlier messages to continue the conversation seamlessly." This requires code execution to be enabled, preserves "your full chat history so Claude can reference it even after summarization", and "Longer conversations that trigger automatic context management consume more of your usage limit." Without it, users see length-limit messages and must start a new chat. — [Claude Help Center, usage and length limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) (WebFetch summary)

Claude Code (agentic CLI):
- Auto-compaction triggers at the model's context limit, with exceptions: Sonnet 4.6/Opus 4.6 without extended context compact at the 200K boundary; native-1M models (Sonnet 5, Fable, Opus 4.7+) compact at approximately 967K tokens by default; cloud sessions compact as the conversation approaches the limit. Adjustable via /autocompact (100K-1M), --autocompact flag, or CLAUDE_CODE_AUTO_COMPACT_WINDOW. With DISABLE_COMPACT the session stops with a context-limit error. — [Claude Code, Model configuration](https://code.claude.com/docs/en/model-config)
- What the compaction summary keeps: "your requests and intent, key technical concepts, files examined or modified with important code snippets, errors and how they were fixed, pending tasks, and current work. It replaces the verbatim conversation: full tool outputs and intermediate reasoning are gone." After compaction Claude Code reloads system prompt, CLAUDE.md, auto memory and MCP tools, re-reads up to five most recently modified files, and re-injects invoked skills capped at 5,000 tokens each; the skill listing does not reload. — [Claude Code, Explore the context window](https://code.claude.com/docs/en/context-window)
- Compaction can be steered: "/compact Focus on code samples and API usage", or a "# Compact instructions" section in CLAUDE.md. Compacting is itself a large request because it reads the whole conversation; /clear costs nothing. Claude Code sends the full conversation on every request, so a one-line question in an all-day session still pays (cached) for the whole history. — [Claude Code, Manage costs](https://code.claude.com/docs/en/costs)

ChatGPT and Gemini:
- ChatGPT: third-party explanations state that when a thread outgrows the window "the oldest turns get dropped" or "the interface silently truncates or summarizes earlier messages"; a total window that is shared with instructions, memories and reasoning. — [PCWorld](https://www.pcworld.com/article/3168543/chatgpt-forgets-things-in-long-threads-heres-the-fix.html); [dev.to explainer](https://dev.to/yvoolab/how-to-stop-chatgpt-and-claude-from-forgetting-context-in-long-conversations-dc4) (secondary; via search summary)
- Gemini: no vendor statement on overflow behaviour was retrievable (support.google.com egress-blocked).

### Inferences
- Under every documented mechanism, what survives is either (a) a model-written summary biased toward intent, decisions and pending tasks, or (b) the most recent turns. Neither guarantees retention of an arbitrary world fact from turn 3 unless it is restated in a place the summarizer treats as current state.
- Claude Code's compaction contract (re-inject CLAUDE.md, re-read recent files) is exactly the shape an RPG needs: state in files that are reloaded after compaction, not in transcript prose.
- Because compaction in claude.ai is tied to code execution and "consumes more of your usage limit", relying on it for a long campaign has a plan-usage cost.

### Gaps
- OpenAI's own help-center wording on truncation vs summarization could not be fetched (egress-blocked); only secondary descriptions were available.
- Google publishes no retrievable statement about Gemini app behaviour at the context limit.
- The default summarization prompt used by Anthropic's server-side compaction is not published, so which world facts it would drop cannot be predicted precisely; the docs only say you can replace it.

## Key question 4: What persists across separate chats (memory features, project knowledge, repo files in agentic tools), and what are the size limits?

### Takeaway
Memory features in all three chatbots are selective, model-curated and explicitly non-exhaustive; they are not a reliable ledger. Project/knowledge files (Claude Projects ~200K tokens with RAG expansion; ChatGPT Projects 5/25/40 files by plan) and repository files in Claude Code (CLAUDE.md up to 4 MiB, MEMORY.md index first 200 lines/25 KB, topic files on demand) are the only mechanisms whose contents persist verbatim and can be read back exactly.

### Cited Findings
Claude Code (repository files):
- Two cross-session mechanisms: CLAUDE.md/AGENTS.md instructions and auto memory, both loaded at the start of every session and treated "as context, not enforced configuration". — [Claude Code, How Claude remembers your project](https://code.claude.com/docs/en/memory)
- CLAUDE.md: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Claude Code loads a CLAUDE.md of up to 4 MiB in full and skips a larger file. Imports via @path load at launch (max depth four hops). Path-scoped rules in .claude/rules/ load only when matching files are read. — [Claude Code, memory docs](https://code.claude.com/docs/en/memory)
- AGENTS.md is read directly (v2.1.277+) when no CLAUDE.md exists in or above the working directory; subdirectory AGENTS.md files load when Claude reads a file there. — [Claude Code, memory docs](https://code.claude.com/docs/en/memory)
- Auto memory lives at ~/.claude/projects/<project>/memory/ with a MEMORY.md index and topic files. "The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, are loaded at the start of every conversation. Content beyond that threshold is not loaded." Topic files are not loaded at startup; Claude reads them on demand. Auto memory is machine-local and not shared across machines or cloud environments; memory files are excluded from the transcript retention sweep. — [Claude Code, memory docs](https://code.claude.com/docs/en/memory)
- Startup context illustration: system prompt ~4,200 tokens, MEMORY.md ~680 tokens, environment ~280, in a 200K simulation. — [Claude Code, Explore the context window](https://code.claude.com/docs/en/context-window)
- Session transcripts are deleted after cleanupPeriodDays (30 days by default); /resume is backed by background summarization of previous conversations. — [Claude Code, memory docs](https://code.claude.com/docs/en/memory); [Claude Code, Manage costs](https://code.claude.com/docs/en/costs)

Claude API memory tool:
- The memory tool (type memory_20250818, all Claude 4+ models) lets Claude create/read/update/delete files under /memories that "persist between sessions, building up knowledge over time without keeping everything in the context window"; it is client-side, so the application owns storage. The API auto-injects a system instruction: "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE... ASSUME INTERRUPTION: Your context window might be reset at any moment, so you risk losing any progress that is not recorded in your memory directory." The tool's view command truncates files longer than 16,000 characters; the docs advise capping file sizes and expiring stale files. — [Anthropic, Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)

Claude.ai Projects:
- Project knowledge limit is 200K tokens (about 500 pages); on paid plans Claude automatically switches to a RAG mode when approaching that limit, expanding capacity "by up to 10x" by loading only relevant content. Supported uploads include PDF, DOCX, CSV, TXT, HTML, ODT, RTF, EPUB; individual files up to 30MB. — [fwdslash.ai, What is a Claude Project (2026)](https://www.fwdslash.ai/blog/what-is-a-claude-project) and [Claude Help Center, usage and length limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) (RAG statement confirmed in fetched help-center summary; 200K/30MB figures via search summary of secondary sources)

ChatGPT:
- Memory works two ways: "saved memories" (explicitly asked-for facts, updated automatically by the model) and "chat history" (insights drawn from past chats). "Memory does not retain every detail from every conversation. ChatGPT decides which available information is relevant to a response." The memory summary "will not include everything that ChatGPT remembers". — [OpenAI Help, Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq); [OpenAI, Memory and new controls](https://openai.com/index/memory-and-new-controls-for-chatgpt/) (via search summary; pages egress-blocked)
- Projects: per-project file limits 5 (Free), 25 (Plus), 40 (Pro/Business/Enterprise); 10 files uploadable at once; files stay attached across conversations in the project. Project-only memory "draws context only from conversations already inside that project" and new context "stays inside the project rather than updating your account-wide memory"; once a project is shared it cannot be switched back to default memory. — [OpenAI Help, Projects in ChatGPT](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) (via search summary)

Gemini:
- "Get personalization with memory of your past chats": requires 18+, personal Google account, Keep Activity on; available in the mobile app, web app, Chrome and watch but "not available in certain features, like Gems or Live chats"; deleting a chat stops it being used after a short delay; users can ask "Did you use any info from past chats?". — [Google, Gemini Apps Help 16598469](https://support.google.com/gemini/answer/16598469?hl=en) (via search summary; page egress-blocked); [Google blog, Gemini can now recall past chats](https://blog.google/feed/gemini-referencing-past-chats/)
- Gemini file uploads: up to 10 files per prompt; files up to 100 MB (video 2 GB); Gemini Apps has its own storage limit for saved chats and uploaded files, independent of Drive, and blocks uploads when full. Custom Gems and Saved Info were reported as paid-tier features. — [Google, Upload and analyze files in Gemini Apps](https://support.google.com/gemini/answer/14903178) (via search summary)

### Inferences
- Across all three vendors, "memory" means personalization signals chosen by the model, not a durable fact store; none documents a guarantee that a specific campaign fact will be retained or retrievable, and ChatGPT explicitly says the opposite.
- Only files (project knowledge, repository files, memory-tool files) persist byte-for-byte. Of these, repository files in an agentic tool are the only kind the model can also write to under version control, which is what a turn-by-turn ledger needs.
- The Claude Code index/topic-file split (small always-loaded index, detail on demand, with a hard 200-line/25 KB cap) is a vendor-tested template for a campaign: a short always-loaded state sheet plus per-entity files fetched by ID.

### Gaps
- No vendor states a byte or token limit for ChatGPT saved memories or Gemini past-chat memory; secondary sources speculate but I found no primary figure.
- Claude.ai's Projects file-count/size and the exact RAG trigger point could not be confirmed from a primary page.
- Whether Gemini "Saved info" is still paid-only in 2026 could not be verified.

## Key question 5: What are recommended patterns for external memory (files, structured state, retrieval by ID), and what evidence supports them over relying on the transcript?

### Takeaway
Anthropic, LangChain and the benchmark literature converge on the same pattern: keep the live window small, write durable state to files outside it, load a compact index at session start and pull detail just-in-time; evidence is the focused-vs-full LongMemEval gap, LOCA-bench's finding that context management substantially raises agent success, and Anthropic's own production harness results.

### Cited Findings
- Anthropic (Sept 29, 2025): recommends just-in-time retrieval (keep lightweight references such as file paths and load content at runtime), compaction that preserves "architectural decisions, unresolved bugs, and implementation details" while discarding redundant output, and "structured note-taking / agentic memory" in files such as NOTES.md; cites Claude playing Pokemon keeping "precise tallies across thousands of game steps" and remembering strategy across context resets. Sub-agents return condensed summaries of typically 1,000-2,000 tokens. — [Anthropic, Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Anthropic (Nov 26, 2025) long-running harness: an initializer session creates a progress file (claude-progress.txt), a JSON feature list with pass/fail status, an init script and an initial git commit; each session starts by reading git logs and the progress file, works one feature at a time, marks it done only after end-to-end verification, and updates the progress log before ending. Documented failure modes addressed: premature completion, undocumented progress, incomplete testing, lost context. — [Anthropic, Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- Anthropic memory-tool docs restate the same "multisession pattern" and recommend pairing compaction (keeps active context small) with memory files (preserve what must survive summarization). — [Anthropic, Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)
- Anthropic context-window docs: "For agents that span multiple sessions, design your state artifacts so that context recovery is fast when a new session starts." — [Anthropic, Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)
- Claude Code docs: move procedures out of CLAUDE.md into on-demand skills and path-scoped rules; delegate verbose operations to subagents so only summaries return; hooks can pre-filter a 10,000-line log to the error lines, "reducing context from tens of thousands of tokens to hundreds"; keep MEMORY.md as a one-line-per-entry index with detail in topic files. — [Claude Code, Manage costs](https://code.claude.com/docs/en/costs); [Claude Code, memory docs](https://code.claude.com/docs/en/memory)
- LangChain's four-strategy framework: Write (save outside the window), Select (pull the right information in per step), Compress (keep only needed tokens), Isolate (split context so parts do not interfere); short-term memory is the message history, long-term memory is a cross-conversation store queried and injected as needed. — [LangChain docs, Context engineering in agents](https://docs.langchain.com/oss/python/langchain/context-engineering) (via search summary)
- Evidence: Chroma's ~300-token focused input versus ~113K full history gap (models succeed on focused, degrade on full). — [Chroma, Context Rot](https://www.trychroma.com/research/context-rot) (via search summary)
- Evidence: LOCA-bench finds context management strategies (stale tool-result removal, compaction, memory tools, programmatic tool calling) "substantially improve the overall success rate" as context grows. — [LOCA-bench arXiv 2602.07962](https://arxiv.org/abs/2602.07962) (via search summary)
- Evidence: NoLiMa shows retrieval holds up when the question shares literal words with the stored fact and collapses when it does not, i.e. explicit, consistently-named records are easier to retrieve than paraphrased narrative. — [adobe-research/NoLiMa](https://github.com/adobe-research/NoLiMa)

### Inferences
- The vendor-endorsed pattern maps directly onto a campaign: a short always-loaded "resume" sheet (current condition, active obligations, pending decision) equals CLAUDE.md/MEMORY.md; per-entity records retrieved by stable ID equal topic files; an append-only event log plus git history equals the progress file plus commits; a rendered summary rather than raw scrollback is what should re-enter context after any compaction.
- Because compaction summaries privilege "intent, decisions, pending tasks", a campaign should never rely on compaction to preserve world facts; it should treat every compaction as a session boundary and re-read the state files afterward, which Claude Code does automatically for CLAUDE.md and recently modified files.
- Keeping the live window under the measured effective lengths (tens of thousands of tokens, not hundreds) is both the quality-optimal and cost-optimal choice; the 1M window is useful as headroom, not as a place to keep 40 turns of prose.

### Gaps
- I found no controlled study comparing file-based state versus transcript-only state on a creative/narrative task; all quantitative evidence comes from QA, coding and agent benchmarks.
- LangChain's blog post could not be fetched directly; the framework is cited via its documentation summary.
- No published figure for how much of a compaction summary's content is factually preserved (a "compaction recall rate"); CogCanvas appears to measure this but its numbers were not retrievable.
